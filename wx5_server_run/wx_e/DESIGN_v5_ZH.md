# DESIGN_v5 — 围绕"计划之上的 RL 实时决策层"重新设计的实验（2026-11-16 JST）

> 配套：SURVEY_v5_ZH.md（文献调研）、PREREG_v5.md（冻结的检验与规则）、PILOT_v5.md（本地试点数字）。

## 1. 研究问题
在 ALNS/TSALNS 静态巡检计划之上，面对合成雷暴（风场 + 移动对流单体）、随机故障和紧急巡检请求，
一个学习得到的**实时决策层**（每个决策点在 LAUNCH / HOLD / SERVE×3 中选择）能否在**100% 完成、遵守 12 h 作业窗口与加班预算**的硬约束下，
显著降低运营总代价 J5、失败次数、成本，并提高高优先级紧急任务的准时率？

## 2. 为什么把 makespan 从主指标中拿掉（且不隐藏）
- v4 显示：RL 在 J 上大幅领先（J −19.9%、fails −54%），但 makespan 落后——RL 学会把飞行推迟到收工后风停时。
  这暴露的是**评价设计问题**：收工后的风场衰减 + J 中 0.5·mk 的弱惩罚，让"拖延"成为可利用的漏洞。
- 运营上真正的约束不是"越早结束越好"，而是**班次/加班上限**（疲劳管理标准：一般 ≤12 h/天）与**加班成本**。
  因此 v5：①作业窗口 T_END=H+240 为硬约束（必须 100% 完成）；②加班按站·分钟计入 J5（C_OT=1）；
  ③**加班预算约束** E[加班] ≤ 200（= 调优 N6 的 dev 水平），RL 训练中由拉格朗日乘子对偶上升强制。
  这样 RL 的收益**不能**来自拖延；makespan 降为次要，在附录 ⑦ 中与 v4 口径 J_v4 一起如实报告。
- 敏感性：C_OT∈{0,0.5,2,4} 重新计分；窗口 H+180 / H+300 测试（RL 不重训）。

## 3. 100% 完成：共享可行性层（与方法无关）
| 组件 | 作用 | 版本 |
|---|---|---|
| 不放弃重试、失败后单目标重飞 | 不丢目标 | v4 |
| 能量拆分（预报能量 >0.9 容量拆单目标） | 避免必失败的多目标航次 | v4 |
| 最晚出发（时间 + 方向感知预报能量窗口） | 禁止"等到来不及" | v4 |
| 值勤移交 | 值勤耗尽时转给半径内余量机 | v4 |
| **备用机兜底**（C_BACKUP=200） | v4 Test-B/L 漏完成的根因：单机 SABS 站无人可接 | **v5** |
| **时间再平衡** | 某机剩余计划窗口内做不完 → 尾部目标逐个转给余量最大的机/备用机 | **v5** |
| 作业窗口 H+240 + 收工后风场衰减 | 物理上可完成 | v4/v5 |
试点验证：26,600 次运行，6 种方法 × 8 个场景（含 Test-B 全量 50 图×20 天、Test-L、压力 C、P4a/b、P3、dev），**全部 100%，0 排除**。
窗口 H+120 不可行（A1 仅 88%），已记录为设计依据。

## 4. 方法：约束 ES 训练的决策层
- **状态特征**（48 全局 + 5×10 动作特征，均可观测）：时间、临近预报单体（距离/ETA/接近速度/扫掠）、站点实测风、预报风（+0/+30/+60 min 与趋势）、
  紧急请求（数量/优先级/截止）、全队状态、本机值勤/剩余工作、**窗口余量、加班阶段、全队瓶颈工作量**（v5 新增）。
- **硬约束** → 掩码（共享层）；**期望约束** → 拉格朗日（RCPO / PID-Lagrangian 思想）：
  F = J5 + λ_V·违规 + λ_OT·加班，λ 慢时间尺度对偶上升。试点中 λ_OT 在 ES 试图拖延（加班 380）时升至 ~1.9，把加班压回 ~100–180。
- **学习器**：OpenAI-ES（对偶、CRN、中心秩、Adam），轨迹级目标，固定 250 次迭代（等算力），3 种子。
- 选择：val 池 + dev 一次性评估（PREREG §5）。

## 5. 基线（强且公平）
| 基线 | 含义 |
|---|---|
| A1 / A2 | 照计划立即执行（"无 RL"，只有共享掩码） |
| N1_240 | 风险阈值等待 |
| N6_best | 预期紧急需求的预留规则（Mitrovic-Minic & Laporte 2004；Ulmer 2018 思想），12 配置 dev 冻结 |
| R_N6best / Rfc_N6best | **事件触发的全量重优化**（TSALNS 式 destroy/repair + SA，跨站重分配所有未开始目标；Rfc 预报感知）+ N6 即时动作 |
| POMO_mean | pomo_v2 策略（无 ES 微调） |
| N4fd_32_100ms / RLR_100ms | 公平 rollout（孪生天气、100 ms 决策时限；RLR 以 RL5 为基策略） |
| O | 全知参照（不参与检验） |

## 6. 消融（均 3 种子、同算力）
无天气预报（nf）、无紧急特征（ne）、无加班约束（uc，预期 J5 更低但加班超预算 → 证明约束的必要性）、无 ES（POMO）、无 RL（A1）。

## 7. 测试集与研究
Test-A（主，50 图 × 100 新天）；Test-B（作者 TSALNS 计划，结构分布外）；Test-C（压力）；Test-L（规模：12×150、15×200）；
P4a σ×1.5、P4b 临近预报偏差（鲁棒性）；P3 均匀故障（探索）；窗口敏感性 H+180/H+300；时延（ms_p99）。

## 8. 统计
地图级 Wilcoxon + Holm；天聚类 Wilcoxon；地图×天交叉 bootstrap；rank-biserial；逐种子结果；"确认"=三者同时显著。

## 9. 风险
- 试点仅 1 种子 150 次迭代；服务器 3 种子 250 次迭代，种子间方差未知（报告逐种子）。
- 加班约束在 dev 上满足不保证在 Test-C（压力）上满足 → H2 分场景报告。
- 重优化基线是我们实现的 ALNS-lite（非作者 TSALNS 原码），在文中如实说明。
