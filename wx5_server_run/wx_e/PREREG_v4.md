## 0. 为什么有 v4：v3 的 reward hacking（如实披露）

v3 服务器结果（commit 1eebe13）显示 RL3 在 Test-A 上 J −19.0%（对 N1）、−16.1%（对 pomo_v2），但复核发现：
1. **未完成的计划目标不计入 J**：RL3 平均每天留下 11.1 个计划目标未完成（15.4%），N1 为 3.6（4.8%）。
   把未完成量按 π 计价后，Test-A 的盈亏平衡 π 仅 200（B 222，C 385，dev 47）——RL 的"改进"主要来自少做事（少飞→少失败→少成本）。
2. **makespan 变差 +26.3%**。
3. **算力不等**：ES 有墙钟上限，各 (seed, λ) 实际迭代 168–300 次，未披露。
4. **rollout 截止时间被突破**：截止只在 rollout 之间检查，N4fd_100ms 的 p99 达 546 ms，RLR_100ms 达 1678 ms；10 ms 档退化。
因此 v3 的主张作废。v4 的首要原则：**必须先确保所有任务 100% 完成，再比较其他指标**。

## 1. 主张（唯一主要主张）

在共享可行性层下、**所有方法 100% 完成**的前提下：
- **H1**：RL（3 个种子的均值策略）在 Test-A 上的 J 显著优于**每一个**可实现基线（N1_240、A1、A2、N6_best、pomo_v2 种子均值），
  特别是最强基线（过门槛基线中 Test-A 均值 J 最小者）；
- **H2**：RL 的 makespan 对**最强基线**非劣（δ = +2%）。
- 次要：fails、cost、ontime_h、cvar_h（单独 Holm 族），以及 Test-B/C/L、P4a/b 的稳健性。

## 2. 共享可行性层（所有方法完全相同：RL、N1、A1、A2、N6、pomo_v2、N4f/N4fd/N4p、RLR、O）

实现：`wx2/sim.py`（COMPLETE 模式）、`wx2/const.py`、`wx2/weather.py`。策略只能在掩码允许的动作中选择。
1. **不放弃**：失败后目标不再被放弃（v3 是 2 次失败或 t≥H 即放弃），以单目标行程重新排在队首。
2. **完成窗口**：班次 H=480 min；之后无新警报，仿真继续到 T_END = H + 480 min 以完成剩余工作（计入 makespan 与成本）。
   收工后风场（真实与预报一致）按 exp(−(t−H)/60 min) 衰减，且 t>H 无对流单体/阵风（t≤H 的天气与 v3 逐位相同）。
   这修正了 v3 的人为假象：t>H 时风场/单体被"冻结"在 H 时刻，导致某些目标永远飞不到。
3. **拆分规则**：多目标行程预测能量 > 0.9·cap 时拆成单目标行程。
4. **最晚出发 / 强制出发掩码**（HOLD 被移除并计入 n_forced）：
   (a) 时间：t + DT + 剩余计划工作的保守时间（无风估计 ×(1+0.30)）> T_END − 75 min；
   (b) 能量窗口：某剩余单目标行程按当前时刻发布的预报（方向相关）现在可行（≤0.95·cap 的判据为 ≤cap），
       但 15 min 后不可行（只用决策时刻的信息，无未来真值）。仅 t<H。
5. **移交**：某无人机连单目标行程都放不进剩余 duty 时，其全部剩余计划目标移交给覆盖范围内、duty 余量（扣除已承诺工作）最大、
   且无风往返能量 ≤0.9·cap 的其他无人机（确定性规则，与策略无关）。
6. **紧急保证**：覆盖范围内的紧急请求超期 ≥30 min 时，该无人机只能执行 SERVE（HOLD 与 LAUNCH 被屏蔽）。
7. **结构性不可服务**的请求（不在任何无人机半径内，或无风往返能量 > cap）对所有方法相同，按定义排除，并报告其数量。

## 3. 完成率门槛与不可行实例规则（先于一切其他指标）

- complete(方法, 实例) = 1 当且仅当 所有计划目标完成 且 所有非结构性的紧急请求被服务。
- **门槛**：对每个方法报告 complete 率；任何 <100% 的方法被标记（✗ FLAG），其余指标仅作条件参考（†）。
  RL 的任一种子未过门槛 → H1/H2 不成立。
- **不可行实例（预注册）**：若参考策略 A1（立即出发）与 N1_240 在某 (map, day) 上都未能完成，则该实例对**所有方法**判为不可行并统一排除，报告数量与其天气构成。
  （试点：dev 400/400 与 Test-L 20/20 上所有方法均 100% 完成，故预计排除数为 0。）
- 次要护栏：J' = J + π·(未完成 + 漏紧急)，π ∈ {0,100,200,500,1000}（门槛通过时 J' ≡ J）。

## 4. 训练与选择（等算力）

- ES（OpenAI-ES，对偶扰动，CRN，中心秩，Adam），从 pomo_v2 种子 s 热启动；**在共享层内训练**。
- 目标：F = J + 1000·(未完成 + 漏紧急) + λ_h·late_min_h + λ_c·cvar_h + λ_m·mk。
- **3 个种子 × 2 组 λ**：(λ_h, λ_c, λ_m) ∈ {(1, 10, 0), (1, 10, 0.25)}（第二组含 makespan 项）。
- **固定 500 次迭代**，pop 24 对偶对，batch 24 个 (plan, day)，σ=0.02，lr=0.003，无墙钟上限；6 个运行并行、worker 数相同 → 真正等算力。
- 验证：每 10 次迭代在固定的 64 个训练分布日上评估中心参数；只有验证集 100% 完成的中心才可成为 best。
- **dev 选择**（每个种子一次）：候选 = 两个 λ 的 best ckpt；要求 dev complete=100% 且 dev mk ≤ 1.02 × 最强 dev 基线的 mk
  （最强 = dev 均值 J 最小者，候选：N1_240、A1、A2、冻结的 N6_best、该种子的 pomo_v2 初始）；满足者取 dev J 最小；
  否则取完成率 100% 中 J 最小；否则 J 最小，并标记 feasible=False。
- N6（文献式启发）在 dev 上 12 组网格中按 dev 均值 J（仅 100% 完成者）冻结。
- dev = dev_ours（20 张图）× 6000–6019；训练日、验证日与所有测试日不相交。

## 5. 测试集与统计

- Test-A：test_ours（50 张 Liu 图，ours 计划）× **新鲜天气日 7200–7299（100 个独立天气日）**。
- Test-B：test_ts（作者 TSALNS 计划，计划结构分布外）× 8200–8299。
- Test-C：压力情景（λ=3.5，p_f=0.5）× 8300–8399。
- Test-L（新增，较大实例）：10 张生成图（12 站×150 目标 ×5，15 站×200 目标 ×5；rt.inst.gen 种子 2026，同一 15 km 区域与 Liu 参数；ours ALNS 3 s，λ=0.5）× 9200–9299。
- P4a σ×1.5，P4b 临近预报速度偏差 ×1.3，P3 均匀故障（探索性），均在 Test-A 日上。
- 天气按日播种（同一天所有地图共享天气）→ 除地图层 Wilcoxon + Holm 外，**同时报告天聚类 Wilcoxon 与地图×天交叉 bootstrap**。
  "确认" = Holm<.05 且 p_day<.05 且交叉 bootstrap 95% CI 不含 0。
- H2：单侧 Wilcoxon（地图层，H0：mk_RL ≥ 1.02·mk_B）p<.05 且交叉 bootstrap 上界 < +2%。
- **权重敏感性**：用记录的分量重新计分 J（mk×0.5/×2/×4，失败罚 P×0.5/×2，高优先迟到×0.5/×2，普通迟到×2），策略不重训。
- **时延**：rollout 截止在**仿真内部**检查（Sim.abort_at → RolloutAbort），未完成轮次丢弃；档位 100 ms 与 1000 ms（10 ms 档删除）；
  报告每决策 ms_p50/ms_p99。1000 ms 档在 Test-A 上只跑前 20 天（成本），WX-H 时延帕累托在 dev 上完整跑。
