# V6 复现版本对比

日期：2026-11-02

## 先区分两个“V6”

服务器上早已有 V6 TSALNS，作为 CA-RL 项目的 M0 冻结基线；这次没有从零再造 V6。服务器原实现的关键哈希为：`tsalns_v6.py` `3337783b...e077da9d`、`fidelity_ops_v5.py` `aae6d9a1...a699e971d`、`native/r6_kernel.c` `672c9df3...edafa012`、Linux native binary `45ed9265...e9492f2`。它的正式研究基准使用约 6 秒 wall-clock；`README` 记录主比较请求 `outer_iterations=100000`，而不是 Liu 论文的固定 `Kmax=500`。

Liu 复现工作又冻结了一个完整的 120 地图 x 5 种子矩阵。其旧版（pre-semfix）与服务器 V6 同样使用上面记录的旧 repair/C 源码语义；其新版（semfix）只修复 Python/native repair 2/3 漏掉“已开放但目前没有路线的站点/无人机”接收目标。官方 Java 两个 repair 都考虑这种接收位置。补丁仅作用于 `fidelity_ops_v5.py` 与 `r6_kernel.c`，没有改 TSALNS 搜索控制、参数、目标函数或 Java 源码。

## 同协议的直接比较

这里比较的是**旧完整复现矩阵** `reproduction/reviewer_package/results/full_{P1,P2}` 与**修正版矩阵** `reproduction/reviewer_package_semfix/results/semfix_full_{P1,P2}`。每一对使用相同地图、种子、500 次外层迭代和参数配置：P1 是 Java-code 参数（local=100、weight upper=5）；P2 是 Table A1 参数（local=500、weight upper=0.5）。每个版本各 1,200 次运行。

| 配置 | 旧版可行数 | semfix 可行数 | 成本不同运行数 | 地图平均成本差异（旧版相对 semfix） | 时间均值，旧版 → semfix |
|---|---:|---:|---:|---:|---:|
| P1 | 600/600 | 600/600 | 0/600 | 0.000%（120/120 地图平局） | 2.482 s → 2.472 s |
| P2 | 600/600 | 600/600 | 0/600 | 0.000%（120/120 地图平局） | 4.759 s → 4.769 s |

成本差按 `100 * (old_cost - semfix_cost) / old_cost`；所有 1,200 对的独立目标值逐项完全相同，map-cluster bootstrap CI 因而为 `[0, 0]`。两版完整路线 witness 有少量差异：P1 5/600、P2 5/600；这些行的目标覆盖集合仍相同，成本也完全相同。墙钟均值差约 -0.4%（P1）和 +0.2%（P2），幅度很小且不构成有意义的性能优势。

**结论：搜索质量上没有强弱差别；复现忠实度上 semfix 更强。** 它修正了经 Java/Python/C 微型反例和 209 项算子矩阵确认的语义遗漏，而完整基准未显示成本退化。后续固定使用 semfix 结果；旧结果继续作为不可覆盖的冻结历史，不需要再重复这两套完整矩阵。

## 哪些结果不可直接比较

服务器 CA-RL 项目报告的 M0 数字（6 秒预算、请求 100,000 外层迭代）与 Liu 复现的 P1/P2（固定 500 外层迭代，另有不同 local/ALNS 参数）停止协议不同。即使有相同实例，也不能仅看平均成本就判定哪版更强。历史 6 秒研究表中 M0 平均成本 455.7618、可行率 100%，但它回答的是“研究预算下 M0 对 M1d/PPO”的问题，不是“paper fixed-iteration V6 port 对官方 Java 是否忠实”。

## 为什么做了重跑

旧的 4,200 行审稿包覆盖当时实现，并且其自身审计通过；之后逐算子 Java 差分发现 repair 2/3 有接收范围遗漏。既然目标是以官方实现为基准核查，修改 native/Python 算子后就不能继续把旧矩阵称为修正版本结果，所以只对受影响的 P1/P2 做独立全量重跑。旧包没有删除或覆盖。重跑后 1,200 行成本完全不变，说明该缺陷没有改变这批全量运行的目标值，但并不使修复变得多余：算子语义依然需要正确，且边界/其他搜索轨迹可能触发它。

完整新版执行证据和审计命令见 `reviewer_package_semfix/SEMFiX_FULL_RESULTS.md`。之后继续研究应复用该审计结果；只有模型、算法、参数或运行协议改变时才新增矩阵。
