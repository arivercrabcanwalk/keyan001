## A. Zhao, Zhang & Coelho (2026), TR-E 214:105074

### A.1 问题与建模假设（p.4，假设 (1)–(8)）

- 系统：一辆卡车 + 一架无人机的异构车队；卡车走曼哈顿度量路网，无人机走欧氏度量（p.4）。
- 目标：有限计划期 T 内最大化期望接受请求数，离散决策时刻 K={0,1,...,K}（p.4）。
- 假设逐条（p.4）：
  1. 每个被接受请求恰好由卡车或无人机服务一次；
  2. 无人机一次 sortie 记 σ=(a,b,c)，a∈TON（可起飞点）、b∈V（客户点）、c∈LAN（可回收点）；一次 sortie 只服务一个客户；
  3. 容量：电池上限 Ω 与载荷上限 Q；
  4. 同步/异步：无人机飞行期间卡车不停车、可继续服务其他客户；二者在回收点重新同步；无人机可在地面等待卡车；
  5. 途中作业：a≠c，禁止"卡车原地等待—无人机往返"；
  6. 不可抢占：卡车一旦出发，下一目的地不可改；无人机一旦起飞，本 sortie 的客户点与回收点固定；
  7. 回仓再派/多趟：全部在途请求完成后可回仓待命，并可因新请求再次出车；
  8. 动态天气：无人机飞行时间依时，且在每个决策时刻 k 用实时风数据更新。
- 边界：这是单卡车单无人机、每 sortie 单客户、允许拒单的模型；不是固定站点、多机、多目标多趟、累计 duty 的 Liu 型模型。

### A.2 状态（p.5 §3.3 – p.6）

- 请求 r=(v_r,t_r,d_r,ξ_r)：位置、到达时刻、服务时长、需求量（p.5 §3.1）；R=R_S ∪ R_D，静态请求 t_r=0，动态请求按非齐次 Poisson 到达、聚合强度 Λ(k)（p.5）。
- 路线计划 Θ=(Θ_V,Θ_D)：Θ_V=(p_1,…,p_i,…,p_0)（式 (1)，p.5），p_i=(r_i,ϱ_i,η_i)，η_i=1 表示离开 p_i 时无人机在车上；Θ_D 为 sortie 序列 ⟨p̃_a^l,p̃_b^l,p̃_c^l⟩（式 (2)，p.5）。已执行段与已承诺段不入 Θ（p.5）。
- 状态四分量（p.5–p.6）：S_k=(t_k, Θ_k, r_k, Δ_k)＝决策时刻、当时路线计划、触发本次决策的新请求、当前风 Δ_k=(v_k,φ_k)。
- 决策时刻由请求到达触发，K 为随机变量；k=0 为服务期开始、只用静态请求离线定初始路线（p.6）。
- 审计观察（原文级，不是勘误）：p.5 称四分量是 "mutually independent components"，但 t_k 是 r_k 的到达时刻、Θ_k 由历史动作决定，四者在生成意义上并不独立。这是建模叙述，不能当作"转移核可分解为四个独立因子"的证明；复现时须自行固定条件化顺序。

### A.3 决策/动作（p.6 §3.4 – p.7 式 (3)）

- x_k=(γ_k, Θ^x_k)，Θ^x_k=(Θ^{V,x}_k, Θ^{D,x}_k) 为更新后的路线计划；γ_k 取值（p.7，式 (3)）：γ_k=0 拒单；γ_k=1 接受并派给卡车；γ_k=2 接受并派给无人机。
- 可行决策集记 X_k；"拒单总是可行"（p.7）。
- 动作空间被启发式压缩为 X̃⊂X（p.8）：在线只做"接/拒 + 卡车/无人机分配"，路线由 ECOPIH 插入启发式给出（p.9 §4.1.1、p.10 Algorithm 1）。
- 与本文关系：动作含拒单，本项目合同不允许以拒单降成本；动作粒度（服务/分配）与本项目 `(slot,target)/(slot,RETURN)` 不同。

### A.4 后决策状态与转移（p.7 §3.5；p.9 Step 4）

- 执行 x_k 后确定性转移到后决策状态 S^x_k=(t_k, Θ^x_k, Δ_k)（p.7 §3.5）；维度低于前决策状态，因为 r_k 已被拒或已并入路线。
- 完整转移由三段拼成，正文没有写出显式转移核 P(S_{k+1}|S^x_k)：
  1. 动作→后决策状态：确定性（p.7 §3.5）；
  2. 外生请求：按非齐次 Poisson 到达 Λ(k)，下一个 r_{k+1} 触发 k+1（p.5 §3.1、p.6）；
  3. 风：每个决策时刻用实时观测更新（p.4 假设 (8)），实验中风速 U[0,10] m/s、风向 U[292.5°,337.5°]（p.15 §5.2、p.15 Table 2）。
- 该风过程是逐时刻 i.i.d. 抽样，文中没有风的持续性、没有预报发布/版本/有效期，也没有风的转移方程；因此"天气是外生随机变量、决策时刻可观测"这一结构与本项目相同，但信息结构（预报发布、误差相关、valid time）在 Zhao 中不存在。

### A.5 奖励、目标、Bellman（p.7 式 (4)–(7)）

```
R(S_k,x_k) = 0  if γ_k = 0                        (4)  p.7
           = 1  if γ_k = 1 or 2
V^π(S_0) = E[ Σ_{k=1}^{|K|} R(S_k, π(S_k)) | S_0 ]                       (5)  p.7
π*(S_k)  = argmax_{x∈X_k} { R(S_k,x) + E[ Σ_{i=k+1}^{|K|} R(S_i,x_i) | S^x_k ] }   (6)  p.7
V^{π*}(S^x_k) = E[ R(S_{k+1}, π*(S_{k+1})) + V^{π*}(S^x_{k+1}) | S^x_k ]          (7)  p.7
```

- 初始状态 S_0 的所有决策奖励为 0，因为静态请求必须全部服务（p.7）。
- 目标里没有成本项：旅行成本只以"有限资源（车辆时间、电池寿命）的机会成本"作文字解释（p.7 末段）。因此 Zhao 的目标不是 M_return、不是 Liu 原成本、也没有逐图 C≤C_Liu+1e-7。
- 式 (6) 的期望写在 S_{k+1} 上，而式 (14) 的回归对象是后决策状态 S^x_k（p.13）。这是下标层面的表述不一致；复现时须固定"价值定义在后决策状态"这一读法（解释，不是作者勘误）。

### A.6 p.13 式 (14)：线性后决策 VFA 的精确形式

```
V̂(S^x_k) = ϑ^T φ(S^x_k) = ϑ_0 + ϑ_1 φ_1 + ϑ_2 φ_2 + ϑ_3 φ_3          (14)  p.13
φ_1 = 当前时间（触发第 k 次决策的 t_k）
φ_2 = 返仓时间（按当前计划路线卡车与无人机回到仓库的时刻）
φ_3 = 无人机 slack time（按当前计划路线，无人机待在卡车上的总时长，不含 sortie）
ϑ = [ϑ_0, ϑ_1, ϑ_2, ϑ_3]^T 为待训练参数
```

- 选择规则是受限候选上的近似 Bellman：Ṽ_k(S_k)=max_{x∈X̃(S_k)}{R(S_k,x)+E[Ṽ(S_{k+1})|x]}（式 (13)，p.13）。候选数为 3（卡车/无人机/拒单，两车都可行）或 2（可行的一车 + 拒单）（p.13）。
- 训练（p.13 §4.2）：离线仿真，每次迭代 (i) ε-greedy 前向采样一条轨迹；(ii) 反向计算每个后决策状态的 reward-to-go；(iii) 用递归最小二乘 RLS 更新 ϑ；停止于固定迭代数。离线训练时用最坏地速、且不用 RE（p.9 第 (2) 项）。
- 特征集：BF={φ_1,φ_2}、EF={φ_1,φ_2,φ_3}（p.15 Table 2）。
- 已取得 SI 的表述差异（见 §D、§E）：SI Table 2 把第三特征写作 "Vehicle Synchronization (VS)"，且参数写作 ϑ=(ϑ_1,ϑ_2,ϑ_3)^T（无截距）；主文 p.13 为 "Drone's slack time" 且含 ϑ_0。两处须并列记录，不能只引主文。

### A.7 pp.14–15：greedy-base 的真实 Monte Carlo rollout（H=10/30 是采样轨迹数）

- 基线 greedy（p.14 §5.1.1）：先做可行性检查（能在不违反仓库截止与无人机能量约束下插入即接受），再派给"能最短时间返仓"的车辆。
- rollout（p.14 §5.1.2 – p.15）逐步：
  1. 候选集初始化 X̃_k={x̃^0_k}，x̃^0_k 为拒单；
  2. 对卡车/无人机分别计算服务 r_k 后的返仓时间 ϱ，若 ϱ≤T 则把"接受并派给该车"加入 X̃_k；
  3. 对每个 x̃_k∈X̃_k：生成 H 条采样轨迹，每条轨迹由从 t_k 到 T 按真实请求到达 Poisson 过程随机抽出的 dummy 请求构成，后续决策一律用基策略 π（greedy）；估计 r̂(x̃_k)=(1/H)Σ_{h=1}^{H}Σ_{t=t_k}^{T}Rew（p.15）；
  4. 取 x̃*_k=argmax r̂。
- H∈{10,30} 是每个候选动作的采样轨迹条数（p.14 第 (3) 步、p.15 的 1/H 求和式）；表 2（p.15）把它叫 "Rollout depth (H)" 属术语误导：不是决策步数，也不是随机抖动候选分数。
- 角色：rollout 在 Zhao 中是对照基线（p.14 "we use rollout policies as a benchmark"），不是被提出的方法；被提出的方法是 VFA(+RE)。RG/RG-RE 两族见 p.16 Table 3 列名。
- 与本项目关系：这才是"真实 MC rollout"的可比对象。任何"随机加分/扰动"都不够资格；本项目若做 rollout，须同样"每候选 H 条完整续接 + 冻结基策略 + 共同随机数"。

### A.8 RE 是什么（pp.9/12 + SI 附录 C）

- RE = Route Enhancement，是非学习的路线改进启发式；不是 "rollout evaluation"，不是 REINFORCE。
- 触发与位置：在线阶段每完成一次 VFA 决策就调用一次（p.9 第 (1) 项；p.9 Step 3）；离线 VFA 训练不使用 RE（p.9 第 (2) 项）。
- 结构（p.12 §4.1.3）：
  1. Algorithm 2 卡车路线重构：取无人机下一次起飞点之后的待服务节点集 N，随机打乱后用贪心最便宜插入生成临时卡车路线（p.12 Algorithm 2 第 5–7 行）；
  2. Algorithm 3 受约束节点迁移：对满足载荷的候选节点，枚举起飞/回收对，算最坏风下能耗 E_temp≤Ω 与无人机返仓时间 rt^uav，与卡车直取时间 rt^tr 比较，若 rt^uav≤rt^tr 则迁给无人机（p.12 Algorithm 3 第 5–10 行）。
- 已取得 SI 的附录 C 给出 12 客户算例（SI p.3–p.5）：初始卡车路线 11→6→1→3→9→8→2→0、三条 sortie；重构后卡车 1→3→8→2→0、sortie ⟨1,7,3⟩,⟨3,9,8⟩,⟨8,5,2⟩，把节点 7/9/5 转成无人机任务。
- 意义：RE 是非学习后处理。p.18 表 5 给出加 RE 的奖励提升（1.42%–60.98%），表下注明分母为 with RE：(with RE − without RE)/with RE（p.18）。因此"VFA+RE 的收益"不能整包记到学习头上。

### A.10 18.58% 的确切含义与口径

- 出现位置只有两处正文：
  1. p.1 摘要："wind-aware routing increases the number of accepted requests by 18.58% compared to wind-unaware approaches"；
  2. p.2 贡献 (5)："increased by up to 18.58% compared to the benchmark policies"。
- 因此口径是风信息价值（WA vs WU）的接受请求数提升；不是 VFA 相对 rollout/greedy 的学习增量，也不是 RL 相对 non-RL 的增量。
- 不可复算：p.16 表 3 是 WA 条件下的奖励绝对值，表内没有任何 18.58% 单元；WU 侧数据只在 p.20 Fig. 7 的柱状图中，PDF 未印数值。故分子/分母、是平均还是最大、覆盖哪 12 个情景、算哪个算法，在 PDF 内都无法复算。摘要说 "by 18.58%"，贡献段说 "up to 18.58%"，两处措辞已经不一致。
- 同一比较族还有另一个数：p.22 §6.5(2) 称 WA 相对 WU "can increase by up to 38.51%"（Fig. 7）。18.58% 与 38.51% 不可能同时是同一族的上界；合理解释（假说）是 18.58% 为某平均、38.51% 为某实例最大，但原文未给口径。
- 结论：18.58% 只能作为"作者报告的风信息价值"，不得转用为本项目 RL 优势或 G3/G4 证据；引用时必须同时写出"WA vs WU、Fig. 7、口径不可复算"。

## B. Han, Wu, Zhu & Sun (2026), TR-E 215:105100

### B.1 模型设定与假设（pp.5–6）

- 滚动窗口调度：窗口长度 Δ（例 10–15 min），每窗开始观测"当前已知事件 + 全部无人机状态"快照并求解一个静态子问题；窗内新事件留到下一窗（p.5 假设 1）。
- 假设（p.5–6）：1 滚动/信息快照；2 同型机同质（续航、速度），窗内近似匀速，飞行时间由给定矩阵给出，起降/换电时间吸收进续航或服务时间；3 窗内事件位置/服务时长/最大允许响应时间为已知常数，路网与空域准静态，空域冲突由下层 UTM 保证；4 无人机状态唯一分为"站内待命 / 任务完成未返 / 在返"，一旦开始服务不可抢占、不可插入其他任务；5 下一窗潜在需求只能在区域聚合层预测，准备度按"可达（阈值内）可用机数 − 预测需求"线性度量，不可达的 depot–region 对视为不可行。
- 状态集合 A=A_B∪A_E∪A_R（p.6）。
- 决策内容（p.5）：(i) 派哪些机、每机服务序列；(ii) 窗末 depot 归属（待命重定位、返航机改降）。

(2q) 原文（p.8）：

```
N^next_b = Σ_{i∈A_B, b^start_i=b} (1 − σ^go_i) + Σ_{i∈A_B} x_{i s_i b}
         + Σ_{i∈A_E} φ^base_ib
         + Σ_{i∈A_R, b≠b^orig_i} ψ^rebase_ib
         + Σ_{i∈A_R, b=b^orig_i} ψ^orig_i ,                      ∀b∈B        (2q)
```

关于 (2r)–(2t) 的三个精确要点（本项目最容易误读的地方）：

1. 被共享的是同一个决策变量 N^next_b，不是常数。N^next_b 由 (2q) 内生决定（哪些待命机不动、哪些任务完成机回哪个站、哪些返航机改降），再被 (2r)/(2t) 同时用作总容量上限。因此"每个区域各自拿满整站容量"在公式层面被禁止：Σ_z r_zb 的上界就是这一站的 N^next_b。
2. r_zb 与 s_z 是连续非负变量（(2v)），不是整数机数；λ_z 是区域需求强度。所以 (2r)–(2t) 是一个连续容量分配/运输问题，不是"整机指派 + 路线"。
3. (2t) 用的是 δ_bz N^next_b（每站容量乘以可达指示），而非固定常数上界；不可达对直接压到 0。

补充（p.8–p.9 正文）：(2m)–(2p) 只要求"完成服务序列后能安全到达至少一个 depot"，不要求在窗内真正飞完并到站；因此 (2q) 的 N^next_b 是"窗末按计划会归到 b 的机数"，不是"窗内已物理就绪"的精确遥测。这一点对任何"适配"都是硬约束：把聚合 carryover 当成"下窗一开始就可用"会系统性高估准备度。

### B.5 式 (3a)–(3e)：Stage II 的准备度配置（p.10）

```
min F2 = ω2 P^short Σ_{z∈Z} s_z + ω3 Σ_{i∈A_R} Σ_{b≠b^orig_i} ψ^rebase_ib        (3a)
s.t. (3b) = (2q)   （N^next_b 定义，∀b∈B）
     (3c) = (2r)   Σ_z r_zb ≤ N^next_b, ∀b∈B
     (3d) = (2s)   Σ_b r_zb + s_z ≥ λ_z, ∀z∈Z
     (3e) = (2t)   r_zb ≤ δ_bz N^next_b, ∀z∈Z, ∀b∈B
```

- Stage II 的决策只作用于 A_idle = A \ A_busy：待命机重定位、任务完成机的窗末 depot 归属、返航机继续原站或改降（p.10 §3.2）。Stage I 已承诺的事件分配与服务序列固定不改（p.9 §3 开头、p.10）。
- 复杂度：O(|B||Z| + |A||B|) 变量与线性约束，可用商用 MILP（Gurobi）短时求到最优（p.10）。
- 分解不是原整合 MILP 的精确重构（p.9 明确 "not an exact reformulation"）；靠外层自适应罚 ρ 把准备度后果反馈给 Stage I。

### B.6 非 RL 两阶段 ALNS/MILP 的具体步骤（pp.9–11）

1. 编码：把 Stage I 的"机—事件分配 + 服务序列"编码成等价的 PDPTW 实例：每个事件构造前驱相关节点对，响应截止→时间窗，处置要求→节点服务时间；每机按其初始状态（A_B/A_E/A_R）设一个起点节点，使三类机在同一路线表示下可解；可行路线须同时满足时间窗与续航（p.9 §3.1）。
2. 初始解：按事件紧迫度做顺序插入；候选插入按"响应时间、迟到、续航可行、终点 depot 可行、资源罚"评估（p.9）。
3. ALNS 主循环（p.9）：destroy ∈ {随机移除、最差成本移除、相关移除、整路线移除、截止压力移除}；repair ∈ {贪心插入、regret-2 插入、截止优先插入、资源感知插入}；接受准则为模拟退火；destroy/repair 算子按得分轮盘自适应选择；终止于最大迭代数/时间上限/无改进。
4. Stage I 目标（p.9）：F1 = ω1 Σ_{e∈E}(a_e + β ξ_e) + ρ·|A_busy|。ρ 是算法内部资源使用罚，明确"不计入最终报告目标"（p.9）。ρ 大→少派机、给 Stage II 留容量；ρ 小→并行多派、压响应时间。
5. Stage II：固定 A_busy 的分配与序列，对 A_idle 解 (3a)–(3e)（Gurobi），得到 N^next_b, r_zb, s_z, ψ^rebase（p.10）。
6. 整合评价（p.10 式 (5)）：F^(k) = ω1 Σ(a_e+βξ_e) + ω2 P^short Σ s^(k)_z + ω3 ΣΣ ψ^rebase,(k)_ib；保留 F^best incumbent（p.11 Algorithm 1 第 8–10 行）。
7. 外层自适应（p.10 §3.3、p.11 Algorithm 1）：S^(k)=Σ_z s^(k)_z；若 S^(k) ≥ S^high 则 ρ^(k+1)=ρ^(k)+Δρ；若 S^(k) ≤ S^low 则 ρ^(k+1)=max{0, ρ^(k)−Δρ}；否则不变（第 11–18 行）。收敛：k≥2 且 |F^(k)−F^(k−1)|/max{1,|F^(k−1)|} < ε，或达 K_max（第 19–22 行）。
8. 参数（p.11）：ω1=1.0, ω2=1, ω3=1; β=2.0; P^short=10.0; T*=20.0; M=10000; V=60 km/h; ρ^(1)=4; Δρ=2。但表 4 及其说明用 P^short=8（p.12 表题与正文；p.13、p.17 亦用 8）。
9. 数值环境（p.11）：30 km × 30 km、5 个 depot、9 个 10 km × 10 km 区域；Stage II 用 Gurobi，时限 600 s、相对 gap 0.01；AMD Ryzen 7 4800H。

审计注记（原文内部不一致，非本项目改动）：(i) P^short 在 p.11 的"主参数"是 10.0，而全部报告表格用 8；(ii) S^high, S^low 只给出符号与序关系（p.11 Algorithm 1 输入行），正文未给数值。任何"忠实适配"都必须显式声明取哪一组，不能默默取有利的一组。

### B.7 −2.91% 相对什么：600 s incumbent，不是最优

- 位置：p.12 表 4 与同页正文。
- 表 4（P^short=8）：Small 7/7/2 → F_heu=48.26, F_Gurobi=48.26, Gap=0.00；Medium 13/13/4 → 82.22/82.22/0.00；Large 20/20/6 → F_heu=110.41, F_Gurobi=113.72, Gap=−2.91。
- 定义（p.12 正文）：Gap(%)=(F_heu−F_Gurobi)/F_Gurobi×100%。
- 参照物（p.12 正文）："Because Gurobi does not prove optimality within the time limit for the medium- and large-scale instances, we use the best incumbent feasible solution returned by Gurobi at termination as the reference."
- 因此 −2.91% ＝ 一个大规模实例上、相对 600 s 时限内 Gurobi 最好可行解的目标值优势；不是"胜最优"，不是"距最优 2.91%"，更不是 6s/12s 下相对 Liu 锚点的成本非劣结论。
- 算术一致性检查（本审计计算）：若该次 Gurobi 真的达到设定的 1% 相对 gap，则其下界 LB ≥ 0.99×113.72 = 112.58 > 110.41（启发式可行解），与最小化问题矛盾。故该次运行的实际终止 gap 必然大于 2.91%，即"1% gap"只是设定值、并未达成。表 4 的 "Gap (%)" 列是启发式相对 incumbent 的偏差，不是求解器的 MIP gap；两者不可混读。
- 另注：−2.91% 是单实例、无重复、无 CI、无地图级统计；不能作为"方法优越"的统计证据。

### C.1 被比较的候选族（按任务给定口径定义）

|学习（更新规则）|若有：策略梯度/监督拟合，更新网络参数|Zhao 的 RLS 参数更新（p.13）；任何标准 PG|无新更新规则。当前族没有出现任何先例之外的更新算子|

### C.4 结论（明确写"无独立算法增量"的部分）

1. 与 Zhao 式 (6)–(7)、(13)–(14) 与 pp.14–15 rollout 相比：我方"同信息因果 μ 续接"是同一 rollout / 同一后决策 Bellman，差别只在转移核里放了更丰富的天气—事件流、以及把终局指标换成完整 M_return。→ 无独立算法增量；属"信息源 + 场景 + 目标"替换。
2. 与 Han (2r)–(2t) 相比：共享容量 Σ_z r_zb ≤ N_b 已是原式；"防止区域重复用满整站容量"不能作为差异主张。若引入样本需求，则是场景 recourse/容量控制（已知框架）。→ 无独立算法增量。
3. 与 Zhao RE（p.12, Alg. 2–3）相比：我方若无后处理，则无可比项；若有，它与 RE 同属非学习路线改进，且必须共享预算。→ 无独立算法增量，且不得把其收益记作学习收益（p.9、p.18 表 5 分母）。
4. 与 Han ALNS/ρ/Algorithm 1 相比：这些正是合同禁用的"算子/预算/资源罚选择"；把 ρ 或邻域交给学习器不是新机制，而是违规动作域。→ 不适用。
5. 我方族目前唯一可能成为差异的东西不是算法，而是信息结构：预报发布时刻/版本/valid time 与告警台账构成的条件信息集，以及由此诱导的条件转移核。若要用它主张算法增量，必须证明存在一个同信息 non-RL（含真实联合因果 rollout、场景容量控制、监督 VFA）无法表达的步骤，例如：
   - (a) 发布时刻导致的信息集不可由"同一公共历史 + 同一模型"的 rollout 复现（即需要新的条件化构造，而非只换样本）；
   - (b) 按 slot 的反事实信用分解产生可证伪的不同梯度（不是标准回报差）；
   - (c) 容量—路线耦合的新对偶/割（不是 (2r)–(2t) 的重写）。
   这三项目前都没有在我方材料中出现；本文件不登记、不判定其成立。
6. 因此对当前登记族，§C 的结论是：问题差异成立（固定站、多趟、累计 duty、严格逐图 cap、天气外生流），算法差异不成立（无独立构造/估计/信用/学习步骤）。这与既有 G0_NO_GO_AS_DISTINCT_ALGORITHM_FULLTEXT_AUDITED 一致；本文件不改变 G0/G3/G4 状态。
