日期：2026-11-12。代码：`harness/minmax_alns.py`（由子线程实现，SHA 记录在 `RESULTS_MANIFEST.json`）。

## 0. 一句话结论

成本中性重排（LPT）只是在**作者已有趟划分**内做负载均衡；一旦允许**改变趟划分**，大图上还有很大的真实空间，
而且这部分空间**同时降低总成本**。开发集上最强的一行是 8x80_o1：M_return 240.788 → **159.628（−33.7%）**，
成本 692.529 → **689.432（−3.096）**，80/80 目标各服务一次，admissible，最大单趟能量 0.995 ≤ 1.0，每次 4.8 s。

**这修正了 `G3_REPORT.md` 的一个措辞风险**：11.4% 的成本中性收益确实是免费的，但它**不是**这类问题的上限；
在大图上，改趟划分的收益远大于换标签。

## 1. 设计与合同

- 目标：`min M_return = max_s max_slot(cumulative duty)`；约束：完整原可行解 + station_types/target_station 冻结 + 全局 `C <= C_anchor + 1e-7`（epsilon=0）。
- 关键实现点：因为 `fixed` 由冻结站型决定，成本 cap **等价于一个全局运行分钟预算**；因此每个移动都用**增量时长**把关，不做全量重算。
- 五个阶段（全部是物理路线决策，不是算子选择）：
  1. `init`：锚点原趟，或同一组趟做 LPT 重排；
  2. `harvest`：逐站旅行距离下降（merge / relocate / swap / 精确重排趟内顺序），**单调**：不升 M、不升全局运行分钟 ⇒ 只创造 cap credit；
  3. `rebalance`：对某站完整趟做精确 slot 划分（子集 DP，成本中性）—— 即成本中性类的最强自由移动；
  4. `min-max`：对瓶颈 (station, slot) 做定向 destroy/repair，从 credit 支付多出的回站路程；
  5. `certify`：结束时用独立 `scorer.validate_candidate(epsilon=0)` 复核；不可行或超时则回退锚点并如实标记。
- 确定性：固定 seed（20261112）、固定候选顺序、只在循环边界做一次 deadline 检查、所有随机来自 `random.Random(seed)` 的固定调用序。

## 4. 这改变了什么

1. **成本中性地板不是天花板**。开发集上 4 图（6x50 / 7x65 / 8x80 / 9x95）被严格超越，最大 −20.1%。
2. **大图的空间来自合并趟**：锚点的趟划分在小图上已接近最优，在大图上则留下大量回站路程；合并趟同时降成本与降 makespan，所以 cap 不紧。
3. **G3 的最强合格 non-RL 现在有一个真实实现**：该搜索在 10/10 图上按时交付、全部 admissible、0 次回退。
   此前 `G0_DECISION.md` R-5 指出的『最强 non-RL 尚未被实现合格地建立』在开发集上已经解决。
4. **对 G0 的影响**：结论不变（无新机制），但理由更强 —— 路线级空间确实存在，而一个**非学习**的 min-max 局部搜索就能拿到它；
   因此 RL 若要主张贡献，必须在这个基线上再赢，而不是在作者锚点上赢。

## 5. 与精确最优的关系

- 6 张可精确求解的图上（3x10 / 3x15 / 3x20 / 4x25 / 4x30 / 5x35），ALNS 全部达到精确最优（差 0.0），与 LPT 相同。
